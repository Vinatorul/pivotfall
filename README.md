# Pivotfall

Одноэкранная action-puzzle-аркада на Godot 4: компактные арены, отбрасывание
противников и перестраиваемые платформы. Сейчас реализованы восемь
последовательных graybox-арен с управляемым персонажем, коротким ударом, тремя
типами платформ, ямами, шарнирами и тремя типами противников.

## Запуск

1. Открыть `project.godot` в Godot 4.
2. Нажать `F5`.

Откроется главное меню:

- `ПРОДОЛЖИТЬ` — открыть сохранённую арену; команда доступна только для
  корректного незавершённого прохождения;
- `НОВАЯ ИГРА` — создать или сбросить прогресс и начать кампанию с Arena 01;
  если на диске уже есть любое сохранение, меню сначала просит подтверждение;
- `РЕДАКТОР УРОВНЕЙ` — открыть редактор и затем вернуться в меню;
- `ВЫХОД` — закрыть приложение; в Web-сборке кнопка скрыта.

Выбор перемещается клавишами `↑` / `↓` или `W` / `S`, подтверждение —
`Enter` или `Space`.

Из терминала:

```sh
godot --path .
```

Проверено на Godot 4.6.1.

### Data-driven кампания

Основной запуск открывает главное меню. `НОВАЯ ИГРА` очищает запомненный
debug-выбор арены, создаёт новое сохранение и запускает `CampaignRunner` с
Arena 01. `ПРОДОЛЖИТЬ` загружает арену, записанную в корректном незавершённом
сохранении. Встроенный [campaign.json](campaign.json) служит единым каталогом:
он задаёт порядок Arena 01–08, стабильный ID, путь к JSON и название каждого
уровня. До старта `CampaignStorage` проверяет весь manifest и все восемь
уровней; частично загруженная кампания не запускается.

При первом запуске, переходе вперёд и прямом выборе через debug-меню новая
арена открывается короткой заставкой с названием. Постоянный HUD показывает
текущий прогресс `N / 8`. Победа в Arena 01–07 после задержки результата
заменяет только дочерний runtime на следующую арену. Падение и `R` заново
создают текущую арену без повторной заставки.

После победы в Arena 08 `final_behavior: show_completion` открывает экран
завершения кампании вместо перезапуска уровня. На нём `R` начинает прохождение
с Arena 01, `Esc` возвращает в главное меню, а `F1` по-прежнему открывает
debug-выбор арены. Поведение стартовой заставки и экрана завершения не
изменилось: меню паузы появляется только во время самой игры.

### Сохранение прогресса

Прогресс основной кампании хранится в `user://campaign_progress.json`.
Версия формата `1` содержит ID текущей арены, ID максимально открытой арены и
признак завершения кампании. Успешный естественный переход после победы
сохраняет следующую арену как текущую и открытую. Restart через `R` или меню
паузы, обычная пауза и возврат в главное меню запись не продвигают.

После завершения Arena 08 сохранение помечается завершённым, поэтому
`ПРОДОЛЖИТЬ` становится недоступным. `НОВАЯ ИГРА` может сбросить такое
прохождение после подтверждения. То же подтверждение требуется перед заменой
любого существующего save-файла, в том числе повреждённого. Повреждённое или
несовместимое сохранение никогда не включает `ПРОДОЛЖИТЬ`.

Запись выполняется через проверяемый временный файл с резервной копией
предыдущего состояния; загрузчик валидирует данные и умеет восстановиться из
корректной резервной копии после прерванной замены. Отдельного экрана выбора
уровня пока нет: обычное прохождение продолжается только с сохранённой арены.

Переход на арену через `F1` переводит текущий запуск в debug-режим без
отслеживания прогресса. Последующие победы в этой debug-сессии не меняют
save-файл, поэтому выбор любой арены для проверки не может случайно открыть
уровни или завершить сохранённую кампанию.

Во время арены `Esc` замораживает дерево сцены и открывает меню паузы:

- `ПРОДОЛЖИТЬ` возвращает в игру; повторный `Esc` делает то же самое;
- `НАЧАТЬ АРЕНУ ЗАНОВО` пересоздаёт текущую арену без стартовой заставки;
- `ГЛАВНОЕ МЕНЮ` завершает текущий запуск кампании.

Выбор перемещается клавишами `↑` / `↓` или `W` / `S`, подтверждение —
`Enter` или `Space`. Пока пауза открыта, глобальный debug-селектор `F1`
подавлен.

Сцена ниже оставлена для изолированной regression-проверки standalone runtime
Arena 01 и не является точкой входа кампании:

```sh
godot --path . res://scenes/level_runtime_arena.tscn
```

Smoke-тест базового формата уровня, validator, builder, победы, падения и
standalone restart:

```sh

  --script res://tests/level_foundation_smoke.gd
```

Smoke-тест кампании проверяет атомарный manifest Arena 01–08, заставки и HUD,
переход Arena 01 → Arena 02, `R` и падение без повторной заставки, прямой
debug-переход, гонку `R` с задержкой после победы и экран завершения Arena 08
с новым стартом на Arena 01:

```sh
godot --headless --fixed-fps 60 --path . \
  --script res://tests/campaign_smoke.gd
```

Smoke-тест прогресса проверяет создание и подтверждённый сброс сохранения,
`Продолжить`, checkpoint следующей арены, завершение кампании, изоляцию
debug-сессии, повреждённый JSON и восстановление из временной/резервной записи:

```sh
godot --headless --fixed-fps 60 --path . \
  --script res://tests/campaign_progress_smoke.gd
```

Smoke-тест паузы проверяет остановку дерева сцены, клавиатурную навигацию,
возврат по `Esc`, restart текущей арены без заставки, подавление `F1` и переход

Smoke-тест главного меню проверяет полный маршрут `меню → Новая игра →

```sh

  --script res://tests/main_menu_smoke.gd
```

### Редактор уровней

В главном меню выберите `РЕДАКТОР УРОВНЕЙ`. Из запущенной debug-кампании можно
нажать `F1`, затем `E`. Прямой запуск:

```sh
godot --path . res://scenes/level_editor.tscn
```

Редактор поддерживает обычные и односторонние прямоугольные платформы, одну
точку старта, патрульных, толкачей, стрелков, включаемые платформы, катапульты,
вертикальные лифты и связанные шарниры. В списке уровней есть восемь встроенных
примеров: базовая Arena 01, Arena 02 с отключаемым мостом, Arena 03-like с
толкачом, Arena 04-like с катапультой, Arena 05-like со стрелком, точная по
геймплейной геометрии Arena 06, Arena 07-like с лифтом и экзаменационная
Arena 08 со всеми тремя связками.

- `Q` — выбор; `1`–`5` — пол, игрок, патрульный, включаемая платформа и
  шарнир; `6` — толкач; `7` — стрелок; `8` — катапульта; `9` — лифт;
- инструменты сгруппированы в прокручиваемой палитре, а Duplicate/Delete
  закреплены снизу;
- ЛКМ и drag — размещение, изменение размера пола/ширины платформы и
  перемещение;
- `COLLISION → ONE WAY` в inspector превращает выбранный прямоугольник в
  платформу, сквозь которую можно запрыгнуть снизу;
- `PRESET → STANDARD / EXAM` выбирает один из закрытых наборов поведения для
  толкача, стрелка и катапульты без редактирования внутренних чисел;
- после установки шарнира нужно кликнуть по управляемой платформе; связь также
  можно изменить через `TARGET` в inspector;
- линии на поле показывают связи, а удалённая цель остаётся красной ошибкой,
  которую можно восстановить через Undo;
- стрелки — сдвиг на шаг сетки, `Shift` + стрелки — на один пиксель;
- `Delete`, `Cmd/Ctrl+D`, `Cmd/Ctrl+Z` — удалить, дублировать, отменить;
- `Save` сохраняет проверенный JSON в `user://levels/` и спрашивает перед
  заменой другого пользовательского уровня;
- `F5` или `Test` запускает неизменяемый снимок, `Esc` возвращает в редактор.
- `← Game` возвращает туда, откуда редактор был открыт: в главное меню или на
  текущую арену; последовательные нажатия `Esc` сначала сбрасывают
  инструмент/выделение, затем предлагают выход.

Ошибки блокируют сохранение и тест; предупреждения остаются неблокирующими.
New, Load и выход не могут молча затереть несохранённый черновик.

```sh

  --script res://tests/level_editor_smoke.gd
```

Отдельный smoke-тест schema, геймплейной JSON-миграции Arena 02, builder,

## Управление

- `A` / `D` или `←` / `→` — движение;
- `W`, `↑` или `Space` — прыжок;
- `X` или `J` — короткий удар;
- `R` — перезапустить арену; на экране завершения начать кампанию заново;
- `Esc` — открыть или закрыть паузу во время арены; на экране завершения
  выйти в главное меню.

Удар не наносит урон: он сообщает противнику фиксированный импульс и активирует
шарниры.

## Быстрый выбор арены

Во время кампании в debug-сборке нажмите `F1`:

- `1`–`8` — открыть выбранный JSON-уровень внутри `CampaignRunner`;
- `E` — открыть редактор уровней;
- `↑` / `↓` — перемещаться по списку;
- `Enter` или `Space` — открыть выделенную арену;
- `F1` или `Esc` — закрыть меню.

Пока меню открыто, игра стоит на паузе. В release-сборке отладочный селектор
автоматически отключается; в главном меню и редакторе он подавлен. При переходе
в редактор и обратно сохраняется ID текущего уровня кампании. Прямой выбор
другой арены показывает её стартовую заставку и сразу обновляет экранный
счётчик `N / 8`, но отключает отслеживание постоянного прогресса до конца
текущего запуска.

## Арены

- **Arena 01:** столкнуть патрульного в открытую яму;
- **Arena 02:** ударить шарнир и убрать мост из-под противника.
- **Arena 03:** уклониться от предупреждённого рывка толкача и столкнуть его в
  яму.
- **Arena 04:** ударить шарнир и запустить патрульного с подвешенной платформы
  по дуге в центральную яму.
- **Arena 05:** укрыться от следящего прицела, переждать выстрел и столкнуть
  стрелка в яму у него за спиной.
- **Arena 06:** подставить прицел под недоступный шарнир, дождаться фиксации и
  уйти с линии; выстрел отключит опору стрелка, а промедление столкнёт игрока в
  противоположную яму.
- **Arena 07:** опустить стрелка на лифте, превратив укрытие в защиту, затем
  перепрыгнуть на нижнюю остановку и столкнуть его в шахту.
- **Arena 08:** пройти экзамен из трёх связок: спровоцировать толкача выключить
  мост под собой, катапультой сбросить патрульного, затем опустить стрелка на
  лифте и вытолкнуть его в отдельную шахту.

Победа последовательно открывает следующие арены. Падение игрока перезапускает
текущую арену без заставки; после прохождения восьмой появляется экран
завершения всей кампании.

Ручные `scenes/arena_01.tscn`–`arena_08.tscn` удалены после завершения
миграции. Единственный источник геометрии и правил кампании — `campaign.json`
и восемь JSON-уровней; прежние варианты сцен остаются доступны в истории Git.

## Текущий состав

- восемь одноэкранных graybox-арен размером 960×540;
- персонаж с ускорением, торможением, гравитацией и прыжком;
- короткий удар с визуальным сигналом и перезарядкой;
- патрульный противник, который разворачивается у препятствий;
- толкач с подготовкой, рывком, отбрасыванием игрока и паузой после атаки;
- стрелок, который разворачивается к игроку, ведёт прицел, фиксирует направление
  перед выстрелом и показывает перезарядку;
- ямы, устраняющие игрока и противников по одинаковым правилам;
- один шарнир на механизм с видимой связью до управляемой платформы;
- включаемый мост точно над центральной ямой в Arena 02;
- воздушная платформа-катапульта с предупреждением, фиксированной траекторией и
  автоматическим возвратом в Arena 04;
- укрытие, останавливающее линию прицела и быстрый снаряд в Arena 05;
- недоступный шарнир, отключаемая опора стрелка и обязательное уклонение в
  Arena 06;
- вертикальный лифт, перевозящий персонажей и меняющий линию огня в Arena 07;
- финальный экзамен, объединяющий три типа врагов и три механизма в Arena 08;
- версионированный JSON-формат, строгий validator и общий runtime-builder;
- строгий `campaign.json` как единый каталог и `CampaignRunner`, который
  атомарно загружает последовательность Arena 01–08;
- версионированное сохранение прогресса с безопасной заменой, recovery,
  `Продолжить` и подтверждением сброса;
- главное меню с продолжением, новой игрой, переходом в редактор и выходом из
  desktop-сборки;
- меню паузы с продолжением, restart текущей арены и выходом в главное меню;
- короткие заставки перед новой ареной, HUD прогресса `N / 8` и отдельный
  экран завершения кампании;
- внутриигровой редактор с сеткой, палитрой, inspector, Undo/Redo,
  validation, безопасным save/load, связями шарниров с включаемыми
  платформами, катапультами и лифтами, preview линии огня, стартовой траектории
  и коридора движения, embedded playtest; data-driven типы включают все три
  типа противников;
- data-driven переход между аренами, поражение и restart текущего runtime без
  повторной заставки;
- глобальный отладочный выбор арены по `F1`;
- стены, потолок и пол;
- без финальных ассетов и звука.
